## A03 与证据限制

**A03 是实际验证器缺陷，优先修复。** 当前仓库脚本与历史副本一致：第 16 行先读取 counts，第 19–23 行只以顶层 `rownames(metadata)` 建主键并断言。实施记录为顶层 rownames slot=NULL、ID 在三个嵌套矩阵；该契约无法为这种对象取得所需显式主键。无论 accessor 返回 NULL 还是默认序号，都不能把它当来源 ID。本次只静态确认契约冲突，未在 R 中重现。

最小修复是单独抽出 metadata-only 身份提取入口，以有来源的 `cell.type` 显式行名为主键，分别检查三个嵌套字段的非空、唯一、行数、集合与顺序，按 ID 显式 match 并记录差分/重排。保留顶层原始 NULL 和来源字段；若顶层有显式 ID，额外核对其关系。缺 ID、重复或无法解释的集合冲突应停止。禁止按行数复制 counts 列名；既有 FACS/DC NA 原样保留。counts 数值检查保留在完整输入审计入口，不让 metadata-only 模式触发读取。

后续主控可直接确定“最小修复＋真实输入合法性审计”的新任务范围；这属于输入准备，修验证器不需要开展聚类实验，也无需用户重复提供同一数据。验收须用真实 coldata、记录 1920 来源主键/NULL、三个嵌套 ID 关系、136 未分配与既有缺失；完整输入审计再核验真实 count 文件 SHA、显式基因/细胞 ID、方向与有限非负整数等合法性，保留失败，不能只报告脚本跑通。

**本次未核验：** 三份外部原始文件的存在/字节或 RDS 内容、真实 counts dimnames/基因/数值、GEO count 表头、原始 flow 表 ID 覆盖、原作者 1656 纳入清单、28 细胞修订对当前输入的影响、真实 R 元数据解析、QC、算法实现/环境及正式实验。库中只有原始数据收据；它们是实施记录，不是本审查亲验。网页 E01/E03 是来源观察记录，不是下载正文，未重复网络 403 或浏览器访问。
