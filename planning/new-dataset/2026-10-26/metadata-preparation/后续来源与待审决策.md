## A03：audit_inputs.R 待修契约

受影响文件是仓库现有 `cases/nestorowa_hsc/scripts/audit_inputs.R`；`recovered-branch/` 下副本是历史证据，不应覆盖。本次只登记兼容性缺陷，未修改原脚本，未执行 R。

静态定位：第19行仅取 `rownames(metadata)`，第22行要求其与 count 列名 setequal。真实 legacy 对象顶层 rownames slot=NULL，显式 ID 在三个嵌套矩阵中。该脚本无法从此结构取得所要求的顶层主键，不能报告它已成功审计此输入。其后第46行附近的 `metadata_ids` 输出也依赖同一前提。

拟修复要求：

1. 单独实现元数据身份提取：仅在 `cell.type` 存在显式、非空、唯一 ID 时，将其作为有来源的主键；同时保留顶层 NULL 的原始事实和 ID 来源字段。
2. 顶层若有显式 ID，须验证与嵌套 ID 的关系；若只是隐式序号，不升格为细胞身份。其他嵌套字段分别检查行数、重复、空值、ID 集合和顺序；确有显式 ID 时可用 `match` 产生重排索引并记录，不按位置拼接。
3. 不允许 `rownames(metadata) <- colnames(counts)`，也不允许在缺少嵌套 ID 时复制任何外部列名。缺 ID、重复 ID、集合不一致或无法解释的冲突应停止并保存差分。遇到 FACS/DC 的既有 NA 应保留并标记，不能补值。
4. 将 metadata-only 提取与现有 count 数值检查入口隔离，使当前获准工作不触发 `readRDS(counts)` 或 inspect_values。完整 count 审计仍需后续单独授权。
5. 本轮已知验收基准是 1920 个来源主键、三个封装矩阵 ID 与 GEO 表头一致、顶层 NULL 不消失、136 个 broad 未分配及既有 FACS/DC 缺失保留；不能只把脚本“跑通”当正确。补丁和任何验证工作留给主控按下一阶段范围安排，不运行合成测试或 smoke。
